# СМО «Электронная очередь в отделении банка»

Гусейнов Гусейн Али оглы, группа 5130904/40101, вариант № 28.

Модель имитирует работу электронной очереди с тремя независимыми потоками клиентов, общей зоной ожидания и несколькими окнами операционистов. Время измеряется в минутах.

## Код варианта

- **ИБ** — бесконечные источники. И1 — VIP, И2 — премиум, И3 — обычные клиенты.
- **ИЗ1** — пуассоновский поток каждого источника. Интервалы между приходами распределены экспоненциально с интенсивностью λ соответствующего источника.
- **ПЗ2 (П32)** — равномерное распределение длительности обслуживания на интервале, заданном для вида операции.
- **Д10З3 (Д1033)** — новый талон занимает первое свободное место в буфере. Остальные талоны сохраняют свои места.
- **Д10О3 (Д1003)** — при полном буфере вытесняется старейший ожидающий талон. Новый талон занимает его место, отказ относится к источнику вытесненного талона.
- **Д2П2** — поиск свободного окна по кольцу. После назначения поиск начинается с окна, следующего за выбранным.
- **Д2Б5** — фиксированный пакет талонов из буфера по приоритету И1 → И2 → И3. Талоны одного пакета вызываются по порядку прихода. Окна переходят к следующему пакету после выхода всех талонов текущего пакета, включая талоны на обслуживании. При равном времени прихода порядок задаёт номер талона.
- **ОР1** — итоговые таблицы по источникам и окнам.
- **ОД1** — пошаговый календарь событий и состояние системы.

Обозначения в скобках взяты из описания бизнес-домена. Основные обозначения приведены по таблице вариантов в пособии 2025 года.

## Сборка

Команды рассчитаны на PowerShell и g++ с поддержкой C++17. Выполните их из корня проекта.

```powershell
g++ -std=c++17 -O2 programm/stepMode/BankQueueStepMode.cpp -o BankQueueStepMode.exe
g++ -std=c++17 -O2 programm/autoMode/BankQueueAutoMode.cpp -o BankQueueAutoMode.exe
```

## Запуск

Пошаговый прогон с проверкой вытеснения и смены пакета. После каждого особого события программа ждёт Enter, затем выводит следующее состояние.

```powershell
.\BankQueueStepMode.exe --rates 0.7 1.1 2 --windows 3 --buffer 3 --seed 28 --requests 9
```

Ключ `--no-pause` выводит ту же трассу без ожидания ввода. На каждом шаге видны приход или завершение обслуживания и вызовы к окнам, совершённые в это модельное время. Таблица календаря содержит все запланированные приходы и завершения. После состояния буфера и окон отображаются активный пакет и указатель кольца.

Автоматический подбор количества заявок для заданной конфигурации и отдельный прогон с фиксированным объёмом для сравнения конфигураций.

```powershell
.\BankQueueAutoMode.exe --rates 0.006 0.014 0.18 --windows 2 --buffer 18 --seed 28
.\BankQueueAutoMode.exe --rates 0.006 0.014 0.18 --windows 2 --buffer 18 --seed 28 --requests 20000
```

Без аргументов программы запрашивают интенсивности в консоли. В пошаговой программе также доступен выбор режима. Через `--help` можно посмотреть параметры. По умолчанию используются три окна, десять мест и интервалы обслуживания 5–15 минут для всех операций. `--service MIN MAX` задаёт общий интервал, а `--operation-service ID MIN MAX` переопределяет его для операции. Номера операций: 1 — вклад, 2 — кредит, 3 — консультация, 4 — обслуживание юридических лиц. Модель задаёт равные вероятности этих операций. При фиксированном `--seed` и одинаковых настройках оба режима дают одинаковые итоговые показатели в одной сборке.

## Модель и статистика

Порядок событий задаётся модельным временем. При совпадении времени сначала рассматривается завершение обслуживания. Для каждого особого события диспетчер размещает ожидающие талоны текущего пакета у свободных окон. Новый пакет формируется при отсутствии активного пакета и наличии ожидающих талонов. После заданного числа приходов программа удаляет из календаря будущие приходы и моделирует выход всех оставшихся талонов.

Доля отказов считается от числа поступивших талонов. Время ожидания и пребывания учитывается для всех вышедших из системы, включая вытесненных. Длительность обслуживания учитывается по обслуженным. Для трёх величин программа выводит среднее и дисперсию с делением на число наблюдений. Пустая выборка отображается прочерком. Загрузка окна равна отношению его суммарной занятости к времени последнего завершения.

Автоматический подбор начинается со 100 заявок. Следующий объём рассчитывается по формуле пособия с δ = 0,10, α = 0,90 и tα = 1,643. Когда две ненулевые оценки вероятности отказа различаются менее чем на 10% от предыдущей оценки, программа принимает предыдущий прогон. При отсутствии отказов объём удваивается. Если на пределе в 2 000 000 заявок критерий не выполнен, программа сообщает об этом и показывает последний расчёт.
